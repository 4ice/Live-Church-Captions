# v0.7.4 Implementation Status

Version: v0.7.4

v0.7.4 is built on the v0.7.3 end-of-speech reliability baseline. It combines the planned Room Display/OBS presentation improvement with the high-priority security fixes, while deliberately deferring broader hardening until these controls have passed appliance verification.

## Shared Room Display And OBS Policy

| Requirement | v0.7.4 implementation | Latency and regression boundary |
| --- | --- | --- |
| OBS exposed visibly speculative tail words | Room Display and OBS share `isPolishedPresentationPage`. English drafts are clipped to the server-owned `cue_stable_word_count`, so presentation outputs show words agreed across recognition passes. | Reuses metadata from `SourceUnitBuilder`; no additional model call or server-side hold is added. The audience-phone viewer keeps its faster mutable-tail behaviour. |
| An unstable revision could replace good presentation wording | A presentation revision with no confirmed words retains the last confirmed output. A later revision updates the same cue in place. | No fixed timeout is introduced. Final cues remain authoritative and publish immediately. |
| OBS used a different line-planning width | Room Display and OBS use the same 50-character planning width, measured wrapping, two-line capacity, cue identities, and subtle presentation motion. | OBS transparency and Room Display styling remain surface-specific; exact wraps can still vary with dimensions and font size. |

Translated presentation output is not sliced using the English stable-word count because translated languages can have different word order and token counts.

## Implemented Security Controls

| Finding | v0.7.4 implementation | Compatibility boundary |
| --- | --- | --- |
| First-run setup and password forms accepted cross-site submissions | Setup, login, and Service Leader pairing use an `HttpOnly`, `SameSite=Strict`, ten-minute double-submit token. They accept that token or browser-verified same-origin evidence, including proxy-forwarded addresses. | Public caption pages remain open. A form left open across an upgrade remains usable; explicit cross-site submissions are rejected before password verification. |
| Operator mutations relied mainly on cookie policy | Each operator session gets a secret-bound request token. JavaScript sends it on same-origin unsafe requests; logout and password forms submit it directly. | GET/status calls are unchanged. Caption and translation processing are not delayed. |
| Password guesses were unlimited | Login and password-based pairing allow five immediate failures, then pause for 2, 4, 8, 16, and at most 30 seconds. State is per source/flow, memory-only, expires after 15 minutes, and clears on success/restart. | The message says why the pause exists, how long it lasts, and that captions/viewers are unaffected. No long-lived account lockout is introduced. |
| SMaLL-100 executed a moving custom tokenizer revision | Runtime and all four installers pin immutable commit `8ab680e26a596d2e3d2d2d17ae0f68df1037328c`, verify tokenizer SHA-256 `73c8d2405e9c588582434c9f91327127faf133b9f915b203ed07ba4cd0ca9c92`, and use SafeTensors for the PyTorch model. | Existing converted CTranslate2 models continue to run. Reinstallation uses the pinned source. |
| Optional Argos dependencies and package extraction needed mitigation | Argos is updated to 1.11.0, SentencePiece is pinned to 0.2.1, and every downloaded Argos archive is checked for traversal paths, symbolic links, encryption, excessive expansion, and extreme compression before installation. Church Cap replaces Argos sentence detection with its existing bounded cue, so no Stanza or MiniSBD model is loaded in the translation path. | Argos 1.11.0 still pins Stanza 1.10.1. This residual upstream limitation is documented rather than bypassing the resolver. |
| Authentication files inherited broad default modes on POSIX | Existing and newly written operator-authentication files are restricted to owner-only `0600`. Unsupported filesystems remain non-fatal and produce an Operator security warning. | Windows keeps its existing per-user application-data ACL behaviour. No password, cookie, or login-flow format changes. |
| Public status responses exposed internal deployment details | `/health` now contains only readiness, service status, and version fields. The viewer language payload keeps availability/request data while omitting model paths, resources, scheduler details, and operator configuration. | Audience language selection and update restart polling retain every field they consume. Full details remain in authenticated status and diagnostics. |
| Browser responses lacked consistent low-risk headers | All HTTP responses receive `nosniff`, `no-referrer`, and a conservative Permissions Policy. Login/setup pages keep their existing no-store and anti-framing treatment. | No CSP or global frame restriction is enforced, preserving current OBS, Room Display, and inline operator behaviour. |
| CI used mutable action tags and did not run security checks | GitHub Actions are pinned to immutable commits with read-only repository permission. CI adds high-severity Bandit checks, a core dependency audit, and rejection of committed `.env`, auth, private-key, and certificate files. | CI-only change; no installed runtime path is affected. Optional translation dependency remediation remains a separate compatibility task. |
| Setup and update paths could retain a vulnerable installer | macOS, Windows, Linux, updater, translation, CUDA, and SMaLL-100 install paths pin the tested fixed `pip==26.1.2` before installing packages. | pip 26.1.2 supports Church Cap's documented Python 3.10+ range. Application dependency versions are unchanged. |
| A post-hardening macOS test could start captions while receiving no audio | Both transcription backends now open audio before model loading and report an open stream that supplies exact digital silence for three seconds. The Operator page gives platform-specific permission/routing guidance, including closed-lid/clamshell MacBooks. Its visible/hidden state is synchronised and dashboard cards no longer stretch to equal height around the message. The Permissions Policy no longer denies microphone access. | The warning is advisory and disappears after any real sample. Caption timing, speech thresholds, translation, and viewer paths are unchanged. Windows and Linux use the same backend path and receive platform-specific guidance. |
| Service leaders could see audience demand but could not resolve incoming language requests | The restricted page now receives the same request state as the Operator page and presents a readable top-down Accept/Reject card. It also shows read-only active translation slots, per-language viewer demand, and the existing digital-silence warning. | Accept/Reject reuses the existing bounded translation actions and the restricted session's same-origin token. Provider selection, model installation, performance, update, account, privacy, and maximum-capacity controls remain Operator-only. |
| Operator dashboard card edges drifted out of alignment | Dashboard grid items now stretch to the height of the tallest card in each row, keeping the Caption controls/Sensitive moment, Audio input/Microphone level, and English live feed/Current settings pairs aligned. | Responsive single-column layouts remain content-height cards; caption, audio, and diagnostics behaviour is unchanged. |

## Acceptance Gates

- Application metadata and the legacy updater literal both report `0.7.4`.
- Setup/login/pairing forms require either a valid short-lived token or browser-verified same-origin evidence; explicit cross-site submissions are rejected.
- State-changing operator APIs reject a missing token or cross-site Origin and accept a valid session-bound same-origin request.
- The fifth consecutive bad password attempt returns HTTP 429, a bounded `Retry-After`, and the operator-facing explanation.
- Valid and malicious Argos archive fixtures pass/fail as intended.
- SMaLL-100 runtime and installers use the same immutable revision and tokenizer checksum.
- Existing transcription, cue, translation, viewer, operator, updater, diagnostics, storage, and Service Leader tests continue to pass.
- Public viewer payloads omit internal paths and configuration while preserving language selection and update readiness fields.
- macOS/Linux authentication files are repaired to `0600` without making startup depend on chmod support.
- Every supported setup/update path selects the tested fixed pip release before resolving application packages.
- Both transcription backends open audio before model loading; an open all-zero stream produces a non-blocking Operator warning and does not stop caption startup.
- A paired Service Leader can accept or reject an incoming language request, while missing-token and cross-origin submissions are rejected and the configured active-language limit remains authoritative.

## Deliberately Deferred Hardening

- server-side operator-session revocation lists and per-session identifiers
- stricter WebSocket Origin and connection/rate limits
- a complete Content Security Policy and compatibility-tested frame policy
- signed release metadata beyond the existing updater integrity checks
- password-hash work-factor migration
- optional translation dependency upgrades for the residual Stanza and Transformers advisories

These items should be reviewed after v0.7.4 login, operator-control, translation-install, and live-caption regression tests pass on the Linux appliance.

In Manual language mode, submit an audience request, verify that the Service Leader card drops down over the top section, then test Accept and Reject. 5. Install or reinstall one Base/Argos language pack and run a short translated-caption test.

7. Start captions and speak into the selected input. Confirm the meter moves while the model loads. If it stays at 0%, follow the displayed platform guidance, restart Church Cap after changing OS permission, and retry.
