## Release Description

# Church Cap v0.7.4

Church Cap v0.7.4 builds on the v0.7.3 reliability release with calmer OBS captions and stronger local security controls.

## Improved OBS Captions

- OBS and Room Display now use the same polished two-line renderer and wrapping policy.
- Live English presentation captions expose the cue prefix already confirmed by Church Cap's existing local-agreement processing.
- Unstable revisions retain the last good presentation wording until a confirmed update is available.
- Corrections update the same cue instead of creating duplicate blocks, and final captions still appear immediately.
- The audience-phone feed retains its faster live policy.

## Safer Operator Controls

- First-run setup, operator login, Service Leader pairing, account changes, logout, and operator control requests now require same-origin security tokens.
- Repeated incorrect passwords receive a short, bounded pause after five failures. The page explains the wait and confirms that active captions and connected viewers are unaffected.
- Successful authentication clears the pause; the maximum wait is 30 seconds and no persistent account lockout is introduced.
- Operator authentication files use owner-only permissions on macOS/Linux. Unsupported permission semantics produce an Operator warning without preventing Church Cap from starting.

## Improved Service Leader Language Controls

- Incoming audience language requests now appear on the paired Service Leader page with **Accept** and **Reject** actions.
- The request card drops down over the top section of the screen and uses the existing Church Cap visual theme.
- Operator dashboard card pairs now share aligned top and bottom edges on wide layouts.
- Read-only active translation slots and viewer-language demand help the service leader decide which requests to accept.
- The Service Leader microphone monitor now receives the same digital-silence troubleshooting warning as the Operator page.
- Maximum translation capacity, provider/model installation, performance, updates, account, and privacy settings remain Operator-only.

## Safer Public Responses And Release Checks

- Public health and language metadata omit filesystem paths, internal network details, audio-device information, translation resources, and scheduler state.
- Audience language selection and automatic update restart detection retain the small set of fields they require.
- Low-risk browser headers apply consistently, while CSP and WebSocket policy changes remain deferred for dedicated compatibility testing.
- Setup and update tools pin pip 26.1.2, and GitHub CI now uses immutable action revisions, minimum permissions, security analysis, dependency auditing, and sensitive-file checks.

## Safer Translation Resources

- Base/Argos translation uses Argos Translate 1.11.0 with SentencePiece 0.2.1.
- Argos language archives are checked before extraction for unsafe paths, symbolic links, encryption, and implausible expansion.
- Recommended and Compatibility SMaLL-100 downloads are pinned to a reviewed immutable revision and the custom tokenizer is checksum-verified before execution.
- PyTorch SMaLL-100 loading uses SafeTensors.

## Compatibility Note

Argos 1.11.0 still declares Stanza 1.10.1. Church Cap replaces that sentence-boundary step with the short cue it already prepared, so live translation does not load Stanza or MiniSBD models. Do not use Church Cap's environment to open unrelated or untrusted Stanza model files; this upstream pin will be reviewed again when Argos publishes a compatible fixed dependency set.

If Start captions succeeds but the microphone meter remains at 0%, the selected device may be open while the operating system or mixer supplies digital silence. Church Cap now reports this state after three seconds. On macOS, the built-in MacBook microphone may be unavailable with the lid closed in clamshell mode; open the lid or select an iPhone, USB, or other external input. Also grant the launching app (usually Terminal) access in **System Settings > Privacy & Security > Microphone**, fully restart Church Cap, and check the selected mixer/interface route. Equivalent Windows and Linux guidance is shown locally.

## Recommended Validation

Test login, start/stop, one saved setting, logout, Service Leader pairing, and the normal audience/Room Display/OBS views on the target appliance. If translation is used, reinstall one Base language pack and run a short translation test before a live service. AI captions and translations can still contain mistakes, so Church Cap remains an accessibility aid rather than a guaranteed verbatim record.
